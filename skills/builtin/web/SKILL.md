# Web

1. Follow the existing stack and entry points; do not introduce a build tool casually.
2. Keep structure, presentation, and behavior coherent at common desktop sizes.
3. Prefer local assets and avoid remote runtime dependencies unless requested.
4. Preserve keyboard access, readable contrast, and useful empty/error states.
5. Run syntax/build checks and a focused DOM or smoke test for core behavior.
